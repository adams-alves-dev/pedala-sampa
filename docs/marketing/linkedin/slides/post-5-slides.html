Por que 170 testes foram baratos

A regra de negócio não mora no componente

✗ Lógica no componente

Montar componente, mockar o CMS, esperar renderização — para testar uma regra de filtro.

✓ Lógica em lib/

Função pura. Escreve entrada, espera saída. Sem montagem, sem mock, sem espera.

Filtros, normalizadores, schemas, formatação de tempo: 21 módulos que não sabem que existe um browser.

O componente fica com o que é dele: apresentar.

Quando testar dói, quase sempre o problema é onde a lógica está — não a ferramenta.

O pipeline

O erro pego antes do CI

1 pre-commit — lint-staged

↓

2 commit-msg — commitlint

↓

3 pre-push — typecheck

↓

4 CI — lint → typecheck → test

↓

5 release-please → tag → deploy

CI vermelho é feedback caro: chega minutos depois, quando você já está em outra coisa.

O mesmo erro pego no commit custa 4 segundos.

A pegadinha

O GITHUB_TOKEN não dispara o próprio workflow

O release-please abre a PR de release. Ao mergear, deveria rodar o workflow que cria a tag.

Não roda.

Por quê

Ação feita com o token do sistema não gera evento para o próprio sistema. É proteção contra loop infinito.

A saída é um PAT.

Depois do release, back-merge automático de main para develop — para as branches não divergirem sozinhas.
